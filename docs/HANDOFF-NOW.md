## 1. 它是什么

本地优先的**个人知识库 AI 助手**：
**Bun 核心 HTTP 服务（127.0.0.1:8770）** ＋ **Swift 菜单栏 App**（`app/C4ememApp.swift`，薄壳：拉服务 / 开窗口 / 常驻菜单栏 / 桌面 Pet）。

知识源：Notion 四库（891 段）、企业邮箱（腾讯企业邮 IMAP）、手机（**ADB**）、Figma / 飞书（诚实的桩）。
检索：FTS5(trigram) + 向量（本机 ollama `qwen3-embedding:0.6b`）两条腿，RRF 融合。

**界面**：右上角三颗模式灯（语音 / 文字 / 结构流）＋ 左侧栏（按软件分区，从功能注册表生成）＋
右侧记录栏（搜索 / 多选 / 批量删除）＋ 左下角来源扇区 ＋ 右下角货架 ＋ 桌面 CEVTUO Pet。

  反编译它的字符串表看出来的四件事，全实现了：
  ① **扇区（`RadialSegment`）不是一个一个圆点** —— 一圈连续的**环带**，每个 App 一个扇形；
  ② **命中按"角度 + 半径"算**（它的 `Selection distance` / `Selection tolerance`），
     **不用 DOM 的 :hover** —— 圆点之间有空隙，指针穿过去的那一下会"谁都不选"，看起来就是闪；
  ③ **A–Z 直接切**（它的卖点 "Power-user keyboard shortcuts (A-Z) for instant app switching"）：

## 6. 反复踩的坑（写代码前扫一眼）

1. **同特异型看顺序** —— 栽过**七次**。加覆盖规则先去文件里 `grep` 那个选择器有几条、谁最后。
2. **改一条已有规则时，没重声明的属性等于没动** —— 不想继承的**全部显式重置**。
3. **类名撞车**：`.card` / `.petbody.card` 那种通用类会被别处的通用规则静默改掉。
4. **量具坏了会被读成产品坏了**：
   - `canvas.toDataURL()` 从外面读 = **已被合成器清空的缓冲** ⇒ 只能在同一个 JS 任务里 `readPixels`；
   - 祖先上的 `filter` **把 3D 压平**；`backdrop-filter` 会成为 fixed 后代的**包含块**；
   - `display:none` 的祖先会让子元素的 computed `display` 也变成 none（过滤器容易假绿）。
5. **网格隐式行按内容撑** ⇒ 比格子大的子元素会**掉到容器外面**（Pet 卡片就是这么"消失"的）。
6. **`WKWebView` 的 hover 只在窗口是 key 时才有**（`.activeInKeyWindow`）——
   刻意不抢焦点的面板要靠**全局鼠标监视器**自己算。
7. **`<img>` 天生可拖** ⇒ 拖动一个带图片的元件，浏览器会先起 HTML5 拖拽（"先拽出一张图才跟上"）。
8. **断言全绿 ≠ 在测东西**：每条断言都要能回答"**它怎么才会红**"；负向对照**只动被测那一侧**。
9. **退化的数据骗得过"单调/在范围内"**：常数序列必须再加一条"至少有 2 个不同的值"。
10. **自制容器拆出来的媒体要验时间轴**，不能只看"能播"。
11. **`if let x = a?.b` 这种 KVC 私有 key 用 `responds(to:)` 判断会返回 false** ⇒
    整句被跳过（`drawsBackground` 那次就是这么让桌面上多了一块白板）。
12. ⭐⭐ **`setPointerCapture` 会把后续的 pointerup / click 重定向到"捕获的那个元素"** ⇒
    子元素上挂的 `click` **永远收不到**（症状就是"点了没反应"）。
    ⚠️ 别用 `e.target` 找子元素（它就是 `#pet`），要 `document.elementFromPoint(e.clientX, e.clientY)`。
13. ⭐⭐ **`addGlobalMonitorForEvents` 收不到"发给自己 App 的事件"** ⇒
    指针一进我们自己的窗就**断流**，而断流正好发生在"移到扇区上"的那一刻（最不能断的时候）。
    ⇒ 改成**定时器轮询 `NSEvent.mouseLocation`**（50ms），没有盲区。
14. ⭐⭐ **"浮动窗"（Pet）里画的东西必须整个落在这个窗里** ——
    锚在右下角的窗，**整圆的底衬右半边和下半边直接出窗**，截出来就是"被齐齐切掉的一块"。
    ⇒ 底衬也得是**弧的一份**（和扇区同一个角度范围），不是整圆。
15. ⭐⭐ **同一条几何判断别拆成两半**（Swift 一半、网页一半）——
    网页知道自己画了多大，Swift 不知道。拆开之后改任一侧都会让另一侧**静默不准**
    （这次的表现是"鼠标在扇区上一闪一闪"）。
16. ⭐⭐⭐ **"窗口尺寸"和"页面视口"在被改的那一瞬间不在同一个坐标系里** ——
    这是 reader 报的「点一下别的就乱闪」的**真根因**（不是阈值没调好）：
    `setFrame` 是同步的，而 WKWebView 里那个**页面视口是异步跟上的**。
    中间那几帧里 `getBoundingClientRect()`（页面坐标）和 `convertPoint(fromScreen:)`（窗口坐标）
    对同一个光标算出的距离**不一样** ⇒ 越过阈值 ⇒ 开-关-开-关。
    实测日志：`CLOSE{"x":289,"y":292,...,"vw":420,"vh":500}` / `OPEN{"x":169,"y":232,...,"vw":300,"vh":440}`
    —— 同一个光标，两次都是 d=86 却一个判开一个判关。
    ⇒ **把窗一次给够，永不 resize**；那块透明区域改由「光标离宠物远就整窗穿透」兜住。
    ⚠️ 调阈值只会让它换个地方抖（这个坑的教训）。
17. ⭐⭐ **切完之后要有一段冷却**，不然"弹一下 → 点一个 → 又弹回来"——
    指针本来就在宠物身上，而切过去的那个 App 会抢到前台。
    ⚠️ reader 报的「点了没反应」和「它自己乱闪」在这里是**同一个根因**。
18. ⭐ **"猜目录"永远漏**（手机相册那次）：系统里有**权威清单**（MediaStore）就一定问它。
    ⚠️ 判据要落在**数量**上（48 vs 6789）—— "命令退出码 0、页面正常渲染"两个版本都满足。
19. ⚠️ **死等固定秒数 = 抖动源**（`verify-pet.mjs` 原来 `waitForTimeout(1300)`，
    实测连跑三次红的是 silver / silver / pearl，每次都不一样）。
    ⇒ 换成**等条件**（等 `dataset.form` 写上），但**别等下面那条断言要查的东西**（那会变成永远绿）。
21. ⭐⭐⭐ **非 key 窗口的"第一次点击"默认是被吞掉的**（AppKit 的 `acceptsFirstMouse`）——
    读者报的「**每个软件都要双击两次才能打开**」和「**拖动卡片不动**」是**同一个根因**：
    第一次按下只用来"激活窗口"，根本没进网页 ⇒ `pointerdown` 没发生 ⇒
    后面一路 `pointermove` 全被 `if (!dragging) return` 挡掉 ⇒ **一条 `drag` 都不发**。
    ⇒ `WKWebView` 子类覆写 `acceptsFirstMouse → true`（见 `PetWebView`）。
    ⚠️ 判据必须是**桥里有没有 `drag` 消息**，不是"看着像挪了"——
      这个坑从第一版就在，一直没人发现就是因为没人去数那几行日志。
22. ⚠️ **Swift 里的常量别做成"类里的 `let`"**：要在 Timer 闭包里用就得处处 `self.`
    （编译期直接报错）。文件级 `private let` 最省事。
23. ⭐ **加"等条件"的时候，超时不许把整条套件带走**：
    `await waitForFunction(...)` 超时会**抛异常** ⇒ 后面几十条断言一条都不跑，
    输出里只剩一句"跑不起来"（真正的红被淹掉了）。
    ⇒ `.then(()=>true).catch(()=>false)` + 那一组单列成 **SKIP**（汇总行也要带跳过数）。
25. ⭐⭐ **"要点一下才能用键盘" = 少了一个 key window** ——
    `.nonactivatingPanel` 天生就是"能拿键盘、但不把整个 App 抢到前台"，**只 `makeKey` 就够**。
    ⚠️ 别顺手加 `NSApp.activate`：那会把用户正在写的 App 推到后面，
    而**鼠标路过宠物**也会触发（用户根本没打算切走）。
    ⚠️ 探针：`pet-bridge.log` 里记 `isKeyWindow` —— 它和控制台一样，不看就永远不知道。
26. ⭐⭐ **改了"点下去发什么"，断言必须一起改，而且两条路都要测** ——
    `pick` 从 HTTP 改成原生桥之后，套件的 HTTP 路由拦截**一条都没走到**（4 条红）。
    反过来更危险：**只盯旧那条路的断言，会在改动上线的那一刻静默变绿**。
    ⇒ 现在有桥 / 无桥各一条断言，而且比的是**路径**（不是"名字里有没有那几个字"）。
28. ⭐⭐⭐ **"我用合成按键验过的"是假证据 —— 2026-10-11 我因此给读者下过一个错结论** ——
    我写的是"只 `makeKey` 就够，别 `NSApp.activate`"，依据是
    `osascript ... keystroke "c"` 打过去、Chrome 起来了。
    ⚠️⚠️ 但 **System Events 的合成按键是"投递给目标"的，真键盘发给的是"当前活动的 App"**
    —— 两件事在这里恰好都成功，我就把"面板是 key"当成了充分条件。
    读者的真键盘立刻拆穿：悬停展开后敲 C **什么都不发生**。
    ⇒ 判据必须是**外部的、和真键盘同一条路**的：`lsappinfo front`
      （它明确打印 `"Cevtuo C4emem" (in front)`）。**别用自己的探针验自己的假设。**
29. ⭐⭐ **`.nonactivatingPanel` 能拿键盘 ≠ 能收到真键盘** ——
    非活动 App 的面板可以成为 key window，但**按键只会送给活动的那个 App**。
    要让轮盘接得住 A–Z，**必须真的 `NSApp.activate`**；
    代价是收起时**一定要把焦点还回去**（`releasePetFocus`）。
    ⚠️ 我加过 350ms 延迟想避开"鼠标路过"，又**撤掉了** ——
      那会让"悬停展开→马上敲字母"偶发失灵，而**偶发失灵比被抢一下焦点难查得多**。
28. ⭐⭐⭐ **"按了没反应"这种故障，别赌单一通路** —— 2026-10-11 读者「按 C 打不开 chrome」，
    我把能查的都查了：`focusState key=true responder=true active=true`、`document.hasFocus()=true`
    —— **四个条件全成立，而他那边就是不行**。
    ⇒ 与其继续赌那一条路，不如**再加一条从原生直接进来的**：
      `NSEvent.addLocalMonitorForEvents(.keyDown)` → `evaluateJavaScript("__petKey(...)")`。
      它只依赖"我们的 App 是活动的那一个 + 窗口是 key"，**不经过网页的响应链/焦点**。
      ⚠️ 命中要 `return nil` **把键吃掉**，否则两条路会把同一个字母处理两遍。
      ⚠️ 带 ⌘/⌃/⌥ 的不碰（别抢用户自己的快捷键）。
    ⚠️ 而且**两条路各写一条断言** —— 只测一条，另一条坏了没人知道。
29. ⭐⭐ **别把"看不见的状态"留在屏幕上没人知道** ——
    这一版在轮盘下面加了一行 **`⌨ 已接通 · 直接敲字母就开` / `⌨ 未接通 · 先点一下它`**
    （三条件同时成立才算接通）。"敲了没反应"以前完全无从下手；现在**一眼就知道是哪一环**。
    和"崩溃 ≠ 失败要长得不一样"是同一族。
27. ⭐ **"乱闪"先问"谁在关它"** —— 加一行 `new Error().stack` 到日志里，一次就定到
    `pick()`（也就是**真的有人在点扇区**）。没有这一行的时候，那串 OPEN/CLOSE
    看起来像"产品自己发疯"，实际上是三种不同来源（点击 / 冷却 / 几何）混在一起。

34. ⭐⭐⭐⭐ **"我们占着前台"时，没有任何一条路能叫动别的 App —— 而且三条路都会报"成功"**（2026-10-11，最贵的一条）
    症状：读者「**点应用按钮也打不开软件**」，我这边日志一切正常。
    实测（三条各自单独试过）：
    · `NSRunningApplication.activate(from:options:)` → 返回 **true**，前台没变
    · `osascript -e 'tell application id X to activate'` → **没有报错**，前台没变
    · `open -a /Applications/X.app` → **没有报错**，前台没变
    `lsappinfo front` 三次都还是 `"Cevtuo C4emem" (in front)`。
    **根因**：macOS 从 Sonoma 起不允许 App 互相抢前台；而我们刚为了键盘焦点
    `NSApp.activate` 过 —— **当前活动的那个 App 不让渡，别人就上不来**。
    `NSApp.yieldActivation(to:)` **不够**，要**真的先不活动**。
    ⇒ 正确顺序（`launchFast` 里就是它）：
      ① `petWindow?.orderOut(nil)` + `NSApp.deactivate()`   ← 先把自己从屏幕和激活位上撤下来
      ② `NSApp.yieldActivation(to: target)` + `activate(from: .current, options: [])`
      ③ **0.55 秒后**再放回宠物，而且**必须用 `order(.above, relativeTo: 0)`**，
         **不能用 `orderFrontRegardless()`** —— 后者**会把前台又抢回来**
         （目标刚上来 1 秒又被顶下去，用户正好在这时候打字）。
    ⚠️ 判据只能是**外部的**：`lsappinfo front` 在 **+0.3s / +1.2s / 光标挪走之后**都该是目标 App。
      只看自己日志里的 `activate ok=true` 会得出完全相反的结论（这次就是）。
    ⚠️ 这又是一次"**操作者收到成功回执、事情没发生**"——本项目的头号反派。


34b. ⭐⭐⭐⭐ **"不能叫动别的 App"的最终版结论（2026-10-11，读者一句话点破）** ——
    读者原话：「**之前是半扇形有阴影那会儿是可以做到的，改回现在这套界面之后就不行了，
    但我还是喜欢现在这套界面**」。
    ⇒ 他记的没错：**那会儿我们根本没抢键盘焦点**，所以后来加的 `NSApp.activate` 才是元凶。
    真正的规则：**当前活动的 App 不让渡，就没有任何别的 App 能被叫到前台** ——
    而且 `activate(from:options:)` / `osascript ... activate` / `open -a` **三条路全都返回"成功"**
    （前两条连错误码都没有），只有 `lsappinfo front` 会说真话。
    ⇒ 顺序（`launchFast` 里就是它）：**先 `orderOut` + `NSApp.deactivate()` 让位 → 再 activate**；
      放回宠物**必须用 `order(.above, relativeTo: 0)`**，`orderFrontRegardless()` 会把前台又抢回来。
    ⚠️ 判据：`lsappinfo front` 在 **+0.3s / +1.2s / 把鼠标挪走之后**都该是目标 App。
    ⚠️ 注意"鼠标停在宠物身上"时轮盘会（按设计）重新展开并把焦点收回来 —— 那是悬停即开要的。


## 6.6 ⭐⭐⭐ 2026-10-12 复核 ① / ② 时挖出来的四件事（都修了 + 都有断言）

### (1) 轮盘的方块**真的叠在一起** —— 几何的前提算错了
`PER_RING=6` + 弧 144° + m 档中圈 r=84 ⇒ 弦长 **41.8**，而方块宽 **38**，当时的账是
"弦长 ≥ 方块宽"。**这个前提是错的**：方块是**轴对齐**的（没有跟着弧转），
两条边要**分别投影** ⇒ 真正的判据是 `弦长 × max(|cos θ|, |sin θ|) ≥ 方块宽`。
最"斜"的那一对在中点 219.6°（`max=0.771`）⇒ 只允许 **32.2** 的方块。
实测**真的叠了 11.1×6.0 px**（截图里 H 和 A 两个角压着）。
⇒ 边距 **12 → 4**（方块 = 图标 + 4 ⇒ m 30 / s 26 / l 34，三档各留 2~3px 余量）。
⚠️ **半径一个都没动** —— 所以只会"更靠近"，不会把读者要的"别太分散"再推回去。
⚠️ 顺手删掉 `.pwic.on` 里那句 `transform:scale(1.12)`：**它从来没生效过**
（`#pet` 上有行内 `transform`，行内的永远赢类里的），而且真生效会顶到 33.6 ⇒ 又叠上。
选中反馈改成放大**图标本身**（不动 `.pwic` 的矩形，几何契约不受影响）。

### (2) 悬停展开会**抢走用户正在按的键**
轮盘是"鼠标路过就展开 + 当场 `NSApp.activate` 抢键盘"的（A–Z 要的就是这个）。
而**网页那条 `keydown` 没有过滤修饰键**（原生那条 `startPetKeyMonitor` 是过滤的）。
真机日志坐实：`key="Meta"` 紧跟 `key="c"` ⇒ **一个 ⌘C 把 Chrome 叫起来了**。
⇒ `onKey` 加一句：带 ⌘ / ⌃ / ⌥ 的一律不处理。断言 + 负向对照 `NEGCTL=6` 都有。

### (3) 设置里那一块**在骗人**（两种骗法）
· 文案里写着 **markdown 的 `**粗体**`** —— 这是 HTML，原样显示成一串星号（真机截图 9 处）。
· 底下那句警示还写着"现在它是**这个窗口里的浮层**…（已经记进待办）" ——
  **那件事早做完了**（Swift 的 `PetPanel` 就是系统级置顶窗）。把做到了的说成没做到，
  用户只会以为开关坏了。「右键就是这一页」也过期了（右键早改成清单了）。
⇒ 一并改掉，并且**把这一类错做成机器查的**：新套件 `scripts/verify-text.mjs`
  —— 凡"会渲染的中文文案"里出现字面 `**` 就红。
  ⚠️ 这是**第三次**栽同一个坑（部署页 31 处 → 设置抽屉 9 处 → 一扫描又出来 18 行）。

### (4) 真机量具那两件（这次新造的 `scripts/mvtool.swift`）
· 搬/点鼠标 + 报窗口矩形。⚠️ 坐标：命令行收**左上原点**、`CGWarpMouseCursorPosition`
  也收左上，而 `NSEvent.mouseLocation` 是**左下** ⇒ 每次把两个都打出来对
  （`cocoaY == H − quartzY`）。上一轮差 593px 的错就出在这里。
· ⚠️ **按窗口截图别用 `screencapture -R x,y,w,h`** —— 那是**截屏幕区域**，
  压在上面的别的窗口会一起进来（第一次截到一张聊天窗，看着像"我们的窗口没开"）。
  ⇒ 从 `CGWindowListCopyWindowInfo` 取 `kCGWindowNumber`，用 `screencapture -l <id>`。

## 6.14 ⚠️⚠️⚠️ 2026-10-13 深夜（三）：**我把没病的地方改了** —— 0.1.6 的更正

读者：「有一些点击还是调取不到窗口到最前面。**你今天没修改之前是没有问题了的**，
那个版本只是一些之前打开了的软件退出了但是还是显示而已，而你现在越改越错误」。

### 真因（§6.13 里我写的那个结论是**错的**）

我原来归因成"抢焦点的面板会吃掉 mouse-up ⇒ `click` 不来"。**没做负向对照就下了结论。**
真因是我自己引进的：

> 把 `running` 改成"每次现读"之后，**每次展开轮盘都必然再重画一次** ——
> ① `openWheel` 结尾那句 `setSrc(...).then(() => paintWheel())` **无条件**重画；
> ② `setSrc` 拿到新列表后也重画。
> 而 `paintWheel()` 是 `host.innerHTML = …`，**把每一格换成新节点**；
> 读者的手指正好在那一刻按下 ⇒ **按下与抬起落在不同元素上** ⇒ `click` 永远不来。
> （以前缓存命中时那次重画只跨一个微任务，浏览器根本不重画 ⇒ 感觉不出来，所以"改之前是好的"。）

### 改了什么

- `openWheel` 结尾**去掉那次多余的重画**；
- `setSrc` 里**列表没变就不重画**（比 path + name；真变了才画 —— 那才是要修的 bug）；
- **撤回**上一版加的 `pointerdown`「按下就选中」，交互回到原样（按下 → 抬起 → 选中）。
- ⚠️ `body.pw-on #petbody{opacity:0}`（藏卡）也已撤回（见 §6.13）。

### ⭐⭐ 两条要记住的

1. **"以前是好的"是一条证据，要用**：先找**和以前比多做了什么**，再决定动不动交互。
   我照着症状去改了交互 —— 那是"越改越错"的标准姿势。
2. **凡是会 `innerHTML =` 重画的东西，都要问一句"用户的手指现在在哪"。**

## 6.15 ⚠️⚠️⚠️ 2026-10-13 深夜（四）：**"点了没反应/一片白"的真凶是凭据**

读者：「经常很多框架都显示不出来，然后随便点击一下就变白什么都操作不了」
「刚打开软件这个样子存在了特别久，然后纯白完全不可用」。

### 真凶一：自带核心没有凭据 ⇒ `hasLlm=false`（这一条解释了大半症状）

- 配置里写的是 `llm.apiKeyEnv = C4EMEM_LLM_API_KEY` —— **密钥只能从环境变量来**；
- App 起的是**自带核心**，工作目录 `Resources/app`，那里**没有 `.env`**；
- 用户配置的 `envFiles` 指的是 `CEVTUO-Z/.env`，**那里没有这个键**
  ⇒ 一切要用模型的功能全挂，**而界面上看不出原因**（点了像没反应 / 一片白）。

✅ 修法（两处，都在代码里，不靠手工）：
- `startServerIfNeeded` 把 **`~/.c4emem/.env` 灌进子进程环境**（凭据住 App 自己目录 ⇒ 也满足"完全独立"）；
- `build.sh` 首次把仓库 `.env` 复制到 `~/.c4emem/.env`。

⭐ **判据**：`curl /api/stats` 的 `hasLlm`（false→true）+ 打一次 `POST /api/ask`。
实测日志：`凭据：从 /Users/cjw/.c4emem/.env 灌了 1 条环境变量`。
⚠️ **并且是在"把配置还原成原样"之后验的** —— 不然验的是我手改的那一步，不是代码。

⚠️⚠️ **我这一天都被"假绿灯"骗着**：我恰好一直有个 dev server 在跑（带着仓库的 `.env`），
所以 App 一直"正常"；**dev server 一停、App 用自带核心，立刻全白**。
⇒ **验收一定要在"什么辅助进程都没有"的状态下做一次。**

### 真凶二：`loadUI` 先设 `uiLoaded` 再 load ⇒ 失败之后永不重试

`webView.load(url); uiLoaded = true` —— 那一刻核心还没起来（起核心是异步的），
load 拿到"连接被拒"，**标志已经设上了** ⇒ 再也不会重试 ⇒ 白屏一直白。
（读者「很久很久都是全白屏」就是这句。）

✅ 现在：窗口一建出来**同步铺一张「正在启动核心…」的页**（底色同页面纸色）→
**后台轮询等核心真的应答**（`ping()` 阻塞，只能放后台队列）→ 再 load 真界面；90s 超时就把原因写界面上。

### 真凶三（没能复现，但把出口接上了）：WebContent 渲染进程崩溃

"永久纯白"最典型的成因。⚠️ **只有 `webViewWebContentProcessDidTerminate` 会响**，
页面自己的 `onerror` 不会被调用（进程没了），服务端也看不到请求。
原来没接它 ⇒ 白着就白着。现在：记一笔 + 自动重载（连崩 3 次停下铺纸），
`didFail` 也不再留白。日志里能分清"进程崩了"和"连不上核心"。
⚠️ **这一条我没复现出来**（Chromium 72s、App 50s 都正常）—— 如实记成"装了仪表"。

### 数字（"一秒就能用"要拆成两个数）

- **核心是热的**（App 已经开着）：`核心就绪（等了 2ms）→ 界面加载完成 19ms`。
- **冷启动**（App + 核心都没起）：启动页 **10ms** 上屏 → 核心就绪 **1291ms** → 真界面 **87ms**。
⇒ "一秒"指的是**屏幕上必须立刻有东西**，不是"内容立刻全到"。

### 另外两条（读者要求）

- **⌘M 能缩小了**：App 以前**从来没有主菜单**（纯菜单栏 App 只有状态栏那颗菜单），
  而 ⌘M/⌘H/⌘Q 是靠主菜单里的菜单项存在的。已补最小一套。
- **Dock 里有它了**：真凶是代码里 `setActivationPolicy(.accessory)` 把 plist 覆盖回去了。
  判据 `lsappinfo` 的 `type`：`UIElement → Foreground`。
