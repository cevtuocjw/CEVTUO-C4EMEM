## 3. ⏳ 下午要做的：窄屏布局（第 4 条）

### 3.1 根因（已量过，别重新猜）

```
.side  固定 186px  +  .dash 固定 312px  =  498px
.main 是 flex:1
```
⇒ **视口 < 498px 时 `.main` 宽度被挤成 0**，整个工作区完全看不见。

实测（`/tmp/probe-narrow.mjs`，截图在 `out/narrow-*`）：

| 视口 | `.main` | 症状 |
|---|---|---|
| **390px** | `l:498, w:0` | **工作区 0 宽、整个跑到屏幕外**；`docScrollW=498 > 390` ⇒ 横向滚动 |
| 768px | `l:498, w:270` | 内容只剩 270px，很挤 |

⚙️ 附带一个明显的错位：`#modes`（右上角三颗模式灯）是 `.main` 里的 `position:absolute;right:18px`，
而 `.main` 宽 0 ⇒ 它**画到了记录栏上面**，和「新语音/新文字/新结构流」那排按钮**叠在一起**
（截图 `out/narrow-390-flow.png` 里看得很清楚）。

### 3.2 已定的方案（读者 2026-10-09 上午选的，**别再问**）

> **方案 1：两栏收成抽屉，主内容全宽。断点 900px。**

- **≥900px**：三栏并排（现状，不动）。
- **<900px**：`.side` 和 `.dash` **默认收起**，主内容占满宽度；
  左上角一排小按钮把抽屉**滑出来**（盖在内容上，带遮罩）。
- 断点依据：498（两栏固定）+ ~400（主内容起码宽度）≈ 900。

### 3.3 实现要点（**别踩的坑**）

1. ⚠️ **现有的收起机制不能直接复用**：
   `body.rail-off .side{display:none}` / `body.rec-off .dash{display:none}` —— 那是
   **`display:none`（直接没了）**，而抽屉要的是**滑进滑出**（transform + 遮罩）。
   ⇒ 窄屏那条路要**新加**一套（建议 `body.narrow`），不要改现有的收起逻辑，
   否则会连带弄坏 `verify-ui` 里那几条两栏收起的断言。
2. ⚠️ **`#modes` 的定位**要一起改：它是 `position:absolute` 贴在 `.main` 右上角，
   窄屏主内容全宽之后它还压不压到别的东西，**要重新量**（这是它现在翻车的原因）。
3. ⚠️ 断点用 `@media (max-width:899px)`。**CSS 里目前一个断点都没有**
   （756 行里唯一的 `@media` 是 `prefers-reduced-motion`），所以这是从零加。
4. ⚠️ 抽屉打开时别忘了**遮罩的 z-index 要够高**（历史上踩过：遮罩 z-index 太低
   ⇒ 既没变暗也点不到）、以及**焦点/`Esc` 关闭**。

### 3.4 判据（照这个写 `scripts/verify-narrow.mjs`）
- **390 / 768 / 899** 三个宽度下：`.main` 宽度 **> 0**，而且 `docScrollW <= innerWidth`
  （不许横向滚动）。
- **900 / 1440**：三栏都在（`.side` `.dash` `.main` 宽度都 > 0）⇒ 断点两边都要测。
- 窄屏下点抽屉按钮 ⇒ 抽屉真的滑出来（宽度 > 0），`Esc` 能关。
- ⚠️ **负向对照**：把断点去掉（或把 `body.narrow` 的规则注释掉）⇒ 390px 那条必须变红。
  **不动的对照 = 没测**。
